# Load Scheduled Investigations from YAML

AlertLens loads Scheduled Investigations from the YAML file named by the optional `SCHEDULED_INVESTIGATIONS_FILE` environment variable at startup; an unset variable disables the feature. The strictly decoded, mapping-root file contains `scheduledInvestigations` entries with `name`, `schedule`, literal `prompt`, and optional `model` fields and is limited to 1 MiB. Prompts and model selections are operator-controlled plaintext configuration; prompts are not logged, while requested model names may appear in structured logs but not Slack messages or Prometheus labels. An omitted model uses the Holmes default, while an explicitly blank model is invalid and a non-blank value is passed to Holmes as a configured model name for Holmes to validate. The Helm chart renders non-empty values into a read-only ConfigMap and includes its checksum in the Pod template so changes trigger a rollout, while non-Kubernetes deployments can provide the same file directly; runtime hot reload is not supported.
